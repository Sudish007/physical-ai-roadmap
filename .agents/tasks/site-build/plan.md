## Restructuring

The work decomposes into seven sequential features (below). The remaining workflow steps are replaced with one `wf-coder` step per FEAT, then one fixer + reviewer loop (max 2 iterations, pause on exhaustion), then the ship step. Reason: the brief (P3/P4) asks for one commit and one audit per FEAT, the FEATs have a strict file-ownership order (pipeline → shell/audit tooling → pages → tracker → feed → workflow → verification), and a single "implement everything" step would have no intermediate green states. The suggested split is kept with ONE adjustment, recorded here: the browser audit tooling (`scripts/audit.py` port of `shots/mock-audit.py` + `scripts/verify.mjs`) moves from FEAT-007 into FEAT-002, because every later FEAT must prove its acceptance with a numeric browser audit before it commits (P4); FEAT-007 becomes the completion of the verification runner (external-link sampling, `--live`, screenshots, meta table, print) plus the committed local screenshot set and report.

Full self-contained step prompts: `workflow-tail.json` (same folder). Feature files: `features/FEAT-001.json` … `FEAT-007.json`. Coder orientation file: `context.json`. Feature order: `task.json`.

## Decisions (ambiguities D1–D11 and the design leave open; decided here, not sent back to design)

The reviewer verified the renderer claims (`escapedSplit`, bold/italic-in-link) against 14.1.0 and the pipeline's plugin hooks are known to work there; moving to 15.x is an unverified upgrade with no benefit for this content. Upgrade later as a chore. `fast-xml-parser` 5.11.2 exact (Ahead's version).
2. **OF-8: `.cards.best-10` switches to 5 columns from 2400 px**, so the ten cards fill two rows at 2560; the 7 session cards stay at 4 columns (4 + 3). Audit: at 2560 the ten best-10 cards have 2 distinct `top` values and 5 distinct `left` values.
3. **Reading-position restore is included (FEAT-003).** Key `physical-ai-roadmap.v1.readpos` → `{ "<page>": scrollY }`, written on `pagehide`, restored only when the URL has no fragment and the stored value is a finite number ≤ `scrollHeight`. ~25 lines; the brief names it as a nice-to-have and the design already named the key.

## Risks

- **Parser constructs.** 18 links inside bold runs and 32 italic spans inside link texts (markdown-it handles both natively — verified by the reviewer); labels that open a longer bold run (`**[JUDGMENT] Use one …**`) — the chip replaces only the bracket; `|` inside code spans in table rows: none today, and the DR-8 row-arity assertion turns a future one into a build error; URLs with balanced parentheses (`…/0004-3702(91)90053-M`) — markdown-it's link destination parser handles balanced parens; the §17.3 fenced blocks contain backslashes and must stay verbatim in `<pre><code>`; `§` lookbehind regex must skip `§§`, `§N(`, `§ 44801`, `§43`; curly vs straight quotes in §3 (DR-10); `π₀` and other non-ASCII pass through as UTF-8. If any construct renders wrongly, fix the renderer, never the content (D11).
- **Runner egress differs from the PC.** NIST (Cloudflare) may 403 → ship rule (Decision 8); eGazette fails TLS everywhere (shown honestly); github.com `releases.atom` answers 404 transiently → one retry; arXiv export API requires ≥3 s between requests and can answer 503/429 → pacing + retry + 15 s timeout; CMU RI RSS is 600 KB and slow (5 s) → 2 MB cap, 20 s timeout. Fetch failures never fail the workflow (`continue-on-error`), so a dark runner still redeploys from committed data.
- **Pages subpath.** Every URL relative except 404.html's `<base>`; `.nojekyll` written; `data/*.json` fetched with `cache: "no-cache"`; Pages must be enabled by API before the first dispatch (`configure-pages enablement: true` is the fallback); the bot's data commit does not retrigger a run (GITHUB_TOKEN) — fetch, build and deploy are one job.
- **Disk.** 3.95 GB free. Budget: node_modules ≤ 5 MB, dist ≈ 4 MB, fixtures ≤ 1.5 MB, screenshots ≈ 5 MB; scratch only in `$env:TEMP` and removed; no browser or package installs beyond the two dependencies.
- **CSP hash drift.** The inline theme script is one string constant in `templates.js`; the hash is computed from that same string at build; the templates test asserts equality. Any edit to the script changes the hash automatically.
- **Tests must not touch the network.** Fixtures are captured once by the FEAT-005 coder with a scratch script; `tests/helpers.js` maps every registry URL to a fixture and throws on unmapped URLs; one test installs a throwing `globalThis.fetch` for the whole pipeline run.
- **Windows specifics.** `.gitattributes` keeps LF in the repo and fixtures byte-exact; PowerShell 5.1 (`;`, UTF-8 via editor tools only); `verify.mjs` spawns and kills the local server itself so no PID juggling is needed in prompts; msedge channel is present (the mock audit ran on it).
- **Time budget.** arXiv pacing makes a full fetch ≈ 30–60 s; the full `--all` verify (28 pages × 8 widths × 2 themes) ≈ 10–15 min on this PC; FEAT coders run the 7-page-type subset before committing and the fixer runs `--all`.
- **Date arithmetic on My plan** depends on the visitor's clock; the audit uses a relative fixture start date (today − 14 days → "Week 3") so the expectation is deterministic.
